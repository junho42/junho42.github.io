# 포트폴리오 사이트

작업물을 올리는 방법은 **폴더를 만들어 넣는 것** 하나입니다. 올리면 목록과 게시물 페이지가 자동으로 만들어집니다.

## 올리는 방법

`upload/` 안에 **작업물 폴더 하나**를 넣으면 됩니다. 폴더 한 겹이 게시물 하나입니다.

```
upload/
├── 2026웨딩스냅/              ← 작업물 (이 이름이 게시물 주소가 됩니다)
│   ├── Info.json             ← (선택) 제목·장르·설명·링크
│   ├── cover.jpg             ← 목록에 보일 대표 이미지 (없으면 첫 사진)
│   ├── 01.jpg ~ 07.jpg       ← 파일명 순서대로 게시물에 나옵니다
│   ├── link.txt              ← (선택) 영상 주소 한 줄 — Info.json의 link가 없을 때만
│   └── memo.txt              ← (선택) 게시물 맨 아래 들어갈 글 — Info.json의 description이 없을 때만
└── 01_대표작/                 ← 앞에 숫자를 붙이면 목록 맨 앞에 고정됩니다
    └── cover.jpg
```

사진을 폴더에 담지 않고 `upload/` 에 낱개로 올리면 게시물이 되지 않습니다.
반드시 폴더를 만들어 그 안에 넣어주세요.

- **`Info.json`으로 제목·장르·설명·링크를 정합니다.** 저장소 맨 위의 `Info.json`(빈 양식)을 작업물 폴더에 복사해 따옴표 안을 채우세요.

  ```json
  {
    "title": "온 계정이 다 너로 가득한",
    "genre": "Music Video",
    "description": "첫 단락\n\n둘째 단락",
    "link": "https://www.youtube.com/watch?v=..."
  }
  ```

  - `title` — 목록과 게시물에 보이는 제목. 비우면 폴더 이름을 씁니다.
  - `genre` — 목록에서 마우스를 올리면 제목 아래 구분선과 함께 흐리게 나옵니다. 비우면 구분선도 나오지 않습니다.
  - `description` — 게시물 맨 아래 글. 줄바꿈은 `\n`, 단락 나누기는 `\n\n`으로 씁니다. 채우면 폴더 안의 `.txt` 글은 쓰지 않습니다.
  - `link` — YouTube·Vimeo 주소면 게시물 맨 위에 영상으로 들어갑니다. 채우면 `link.txt`는 쓰지 않습니다.
  - 게시물 주소는 제목이 아니라 **폴더 이름**으로 만들어지므로, `title`을 고쳐도 이미 공유한 링크는 그대로입니다.
  - 따옴표나 쉼표가 빠져 형식이 깨지면 그 파일은 무시되고 폴더 이름·`.txt`로 대체됩니다(빌드 경고에 나옵니다).
- **`Info.json`이 없으면 폴더 이름이 제목입니다.** 이름 앞에 `01_`처럼 숫자를 붙이면 그 순서대로 앞에 고정됩니다. 숫자를 안 붙이면 **새로 올린 것이 위에** 옵니다. 서로 다른 폴더가 접두사만 다르고 이름이 같으면(`05_광고`와 `광고`) 주소가 겹치므로 뒤에 온 쪽에 번호가 붙습니다.
- **영상**은 `link.txt`에 YouTube나 Vimeo 주소를 한 줄 적으면 됩니다. mp4 파일을 그냥 넣어도 되지만 25MB를 넘으면 웹에서 업로드가 막힙니다. 영상은 게시물 맨 위에 놓입니다.
- **설명글**은 아무 이름의 `.txt`에 쓰면 게시물 맨 아래에 들어갑니다. 메모장으로 저장해도 한글이 깨지지 않습니다. 빈 줄을 넣으면 단락이 나뉩니다.
- 사진도 영상도 없는 폴더는 그냥 무시됩니다.

올린 뒤 1~2분이면 사이트에 반영됩니다. 사진은 웹용으로 자동 축소되며 **원본 사진은 그대로 보관되고 웹에는 공개되지 않습니다.** (mp4로 올린 영상은 다릅니다 — 리사이즈하지 않고 원본 파일을 그대로 웹에 올립니다. 용량이 크면 그만큼 그대로 웹에 나갑니다.)

혹시 시간이 지나도 반영이 안 되면 저장소의 **Actions** 탭에서 방금 올린 건의 진행 상황을 볼 수 있습니다. 빨간 표시가 뜨면 처리가 안 된 것이니, 다시 올려보기보다는 그 화면을 그대로 알려주세요.

폴더를 지우거나 이름을 바꿔도 **이미 만들어진 게시물 페이지와 사진 주소는 그대로 남습니다.** 목록에서만 빠지고, 그 주소를 아는 사람은 여전히 볼 수 있습니다. 저작권·초상권 문제로 정말 완전히 내려야 하는 경우에는 폴더를 지우는 것만으로 끝나지 않으니 따로 알려주세요.

## 이름·연락처 바꾸기

**페이지 제목, 연락처, Contact 글은 `define.json`** 에 씁니다.

```json
{
  "title": "브라우저 탭에 보이는 페이지 제목",
  "email": "hello@example.com",
  "instagram": "https://www.instagram.com/아이디",
  "name": "이름",
  "phone": "010-0000-0000",
  "address": "서울특별시 중구 세종대로 110",
  "contact-title": "Contact 글 맨 위에 크게 들어갈 한 줄",
  "contact-content": "첫 단락\n\n둘째 단락"
}
```

- `title` — 모든 페이지의 제목(브라우저 탭·공유 미리보기)에 공용으로 들어갑니다. 비우면 `site.config.json`의 `siteName`을 씁니다.
- `name`·`email`·`phone`·`instagram`·`address` — Contact 페이지에 나옵니다. 이메일과 전화번호는 누르면 복사되고, 인스타그램은 링크입니다. 인스타그램은 주소 전체를 적어도, `@아이디`만 적어도 됩니다.
- `address` — Contact에 주소와 함께 구글 지도가 나옵니다. 지도는 이 주소로 검색한 위치라, 핀이 엉뚱한 곳에 꽂히면 도로명 주소로 바꿔 적어 보세요.
- `contact-title` — Contact 글 맨 위에 크게 들어가는 한 줄(각오·마음가짐).
- `contact-content` — Contact 본문. 줄바꿈은 `\n`, 단락 나누기는 `\n\n`으로 씁니다.
- 비워 둔 항목은 Contact에서 빠집니다(`title`만 예외 — 비우면 `siteName`을 씁니다).

그 밖의 값(헤더 왼쪽 상호 `siteName` 등)은 `site.config.json`에서 고칩니다. 고치면 모든 페이지에 반영됩니다.

## 만지지 않아도 되는 것

`works/`, `media/`, `works.json`, `index.html`, `contact.html`은 **자동으로 만들어지는 파일**입니다. 직접 고치면 다음 업로드 때 덮어써집니다. Contact 페이지 글을 바꾸려면 이 파일들이 아니라 위의 `site.config.json`을 고치세요.

## 개발자용

빌드:

```bash
pip install "pillow==12.*" "pytest==9.*"
python tools/build.py          # 전체 빌드
python tools/build.py --check   # 생성물 참조만 검증
python -m pytest tools/tests -v # 테스트
```

산출물은 순수 HTML·CSS·JS이고 외부 참조가 하나도 없습니다(웹폰트도 쓰지 않습니다).
자산 참조가 모두 상대경로라 폴더째 다른 곳으로 옮겨도 깨지지 않습니다.

다만 카드와 이전/다음 링크는 디렉터리 URL(`works/화보/2026웨딩스냅/`)이라 `file://`로
폴더를 직접 열면 브라우저가 그 안의 `index.html`을 자동으로 찾지 못해 페이지 사이
이동이 안 됩니다(CSS·JS·이미지는 정상입니다). 로컬에서 확인할 때는 이 폴더에서
`python -m http.server`를 실행하고 콘솔에 뜨는 주소로 접속하세요.

설계 근거와 실행 기록은 `docs/`에 있습니다.

### 처음 세팅할 때

1. 이 폴더를 새 저장소로 푸시합니다(기본 브랜치 이름은 `main`이어야 합니다 —
   워크플로가 `main` 푸시에만 반응합니다).
2. **Settings → Actions → General → Workflow permissions**를 "Read and write
   permissions"로 바꿉니다. 기본값(읽기 전용)에서는 워크플로에
   `permissions: contents: write`가 있어도 push가 403으로 조용히 막힙니다.
3. **Settings → Pages**에서 배포 브랜치를 `main` / 루트로 지정합니다.
4. `define.json`에서 `title`·`email`·`instagram`·`name`·`phone`·`address`·`contact-title`·`contact-content`를, `site.config.json`에서 `siteName`을 채우고,
   `siteUrl`을 실제 주소로, `noindex`를 `false`로 바꿉니다. `noindex`가 `true`인
   동안은 검색엔진이 이 사이트를 색인하지 않습니다.
5. 확인이 끝나면 예시용 `upload/01_샘플/`을 지웁니다. 지운 뒤 한 번 더 빌드하면
   목록에서 빠집니다 — 다만 `works/샘플/`과 `media/샘플/`은 남으므로 같이
   지워야 주소가 죽습니다(아래 참고).

### GitHub Pages가 아닌 호스팅을 쓸 때

Cloudflare Pages·Netlify처럼 git 연동 호스팅이면 바뀌는 게 거의 없습니다.
빌드 명령만 그 플랫폼에 등록하면 되고(`python tools/build.py`), 나머지는 그대로입니다.

순수 FTP 호스팅이면 네 가지를 직접 챙겨야 합니다.

- **게시물 날짜 정렬이 깨집니다.** 날짜를 git 이력(`git log`)에서 읽기 때문에, git
  없이 폴더만 올리는 방식에서는 전부 현재 시각으로 대체되어 "최신순"이 임의 순서가
  됩니다. 경고도 남지 않습니다. 순서를 지키려면 폴더 이름 앞에 숫자를 붙이세요.
- **디렉터리 URL**: 서버가 `works/화보/작업/` 요청에 그 안의 `index.html`을
  돌려줘야 합니다. Apache·nginx는 기본 동작이지만, S3 정적 호스팅은 index document
  설정이 필요하고 S3+CloudFront는 별도 함수 없이 서브폴더가 깨집니다.
- **`.webp` MIME 타입**: 오래된 Apache·IIS는 `image/webp` 매핑이 없어 브라우저가
  이미지를 표시하지 않고 다운로드합니다.
- **원본 비공개**: `upload/`·`templates/`·`tools/`는 업로드 대상에서 빼세요.
  그러지 않으면 수십 MB 원본이 그대로 공개됩니다.

### 이미지는 Git LFS에 들어갑니다

`upload/` 의 원본(jpg·png·webp·mp4 등)은 `.gitattributes` 설정에 따라 Git LFS로
저장됩니다. 원본은 한 장에 수십 MB가 될 수 있어 일반 git 이력에 쌓으면 저장소가
빠르게 무거워집니다.

**`media/` 는 일부러 LFS에 넣지 않았습니다.** GitHub Pages는 LFS 파일을 서빙하지
않고 LFS 포인터(작은 텍스트 파일)를 그대로 내려보냅니다. 사이트가 참조하는
이미지를 LFS에 넣으면 **모든 이미지가 깨집니다.** `media/` 는 리사이즈 사본이라
용량이 작으니 그대로 두는 편이 안전합니다.

주의할 점:
- 워크플로의 checkout 에 `lfs: true` 가 있어야 합니다. 없으면 러너가 포인터만
  받아 빌드가 이미지를 열지 못합니다.
- GitHub 무료 계정의 LFS 할당량은 저장 1GB·월 전송 1GB입니다. 원본을 계속 쌓으면
  넘을 수 있고, 넘으면 추가 구매가 필요합니다.
- 로컬에서 작업할 때는 `git lfs install` 이 한 번 실행돼 있어야 합니다.

### 생성물 정리는 자동이 아닙니다

업로드 폴더를 지우거나 이름을 바꾸면 목록에서는 빠지지만, 그 게시물의
`works/<제목>/`과 `media/<제목>/`은 저장소에 남아 주소가
계속 열립니다. 내려달라는 요청을 받았다면 그 두 폴더도 직접 지워야 합니다.
